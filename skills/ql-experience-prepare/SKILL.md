# Prepare the actual QL experience

## Contract metadata

- Native source owner: EpiLogos/QL-MEF; Skill discovery/composition/projection owner: AIKit.
- This Method is this Skill's existing source/resource identity.
- Executable support: read-only `scripts/check-ux-spine.py --prepare UXnn` and `--self-test`.
- Standing: preparation and scoped evidence; no runtime or human-validation claim.

## When

Use before implementing, integrating or testing any portion of the current QL living instrument, especially when a fresh agent must recover the user's intended activity. Do not replace the whole source field with a selected demonstration.

## Inputs

Assigned issue/story, actual current repository and relevant owner revisions, available World/Project/NOW and actor, selected subject/ref/source revision, native provider/capability readings, and any existing receipt. The source paths below belong to the canonical QL repository, not the generated Skill directory.

## Authority

Preparation is read-only. Source visibility does not establish agent disclosure or mutation permission. Central is the root meta-Project and owns Day/NOW. No private setup change, DB connection, source adoption or unattended act is implied.

## Procedure

1. Read `docs/KERNEL-REBUILD-WAYFINDER.md`, `docs/kernel-rebuild/UX-INTENT-SOURCE-MINUTE.md`, and the assigned story in `UX-SPINE-RECONCILIATION.md`. Follow the existing Cradle 04 §2 spine and 03 state family links. Use owner conversation, issues and maps for intent; never PR narratives.
2. Read `AGENT-PRACTICE-AND-BOOTSTRAP.md` and the relevant full source matrices/locks. Record the whole-field obligation and the exact owned implementation files. Inspect active issue coordination before branching.
3. In a verified source checkout run `python3 scripts/check-ux-spine.py --prepare UXnn`. With only the native connector, read the same source and record that the command was not run. Do not invent an installed path.
4. Establish root versus child Project from the actual owner, the current subject/source/instance, actor, NOW and selected disclosure. Verify the actual Skill description/source, native discovery, current projection and any harness-loading evidence separately.
5. Inspect real Action/tool descriptions and input/result schemas. Name the supported route, prerequisites, authority and failure/recovery. A declared capability or existing Rust type alone is not a callable agent affordance. Use the bounded generic QL operation Method only within its supported service scope.
6. Return a preparation record with each dependency observed or unresolved. Implementable repository gaps remain work in their native owner. Missing local access blocks only the corresponding installed test. Preserve the user's newer renderer and accepted M1–M3 waves.

## Outputs

The selected UX story and A/B obligations; original intent/source; actual root/child and subject basis; practice/source/loading state; native operation and prerequisites; exact supported/blocked branches; evidence references and next owner action. Source-only output is labelled source-only.

## Verification

Run `python3 scripts/check-ux-spine.py --self-test`. For native delivery use `scripts/verify-ux-skill-projection.py`; actual live harness loading/use and human judgement require their own walk. Neither static check upgrades the readiness record.

## Failure and recovery

A missing source is a named access gap, not invented content. A stale/wrong-world binding stops that operation. No shell/API fallback to an unknown owner. Do not repeatedly retry unsupported tools; use the actual native schema or record the exact unavailable action. Preserve partial evidence and continuation.

## Continuity

Return the bounded preparation to the existing issue or authorised Central NOW, with exact versions and unresolved dependencies. Do not create a second master plan or twelve T/T′ files. The next participant must recover the same subject, intention and state.
