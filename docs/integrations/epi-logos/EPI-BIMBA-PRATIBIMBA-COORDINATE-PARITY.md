**Status:** development protocol / Wayfinder guard

## Why this is now a programme-level guard

The first lived M4′ Nara vertical exposed an architectural distinction which must apply to all subsequent Epi instrument work.

A useful vertical can be semantically too narrow even when its individual feature is correct. Prompt B correctly built the M4′ daily journal, DAY/NOW, protected persistence, profile context and selected-context sendoff, but its initial provider contract addressed Nara mainly at the M4′ root plus the daily episode. The authored Nara source is more articulated: M4 contains M4-0 … M4-5, each has its own sixfold differentiation, #4.4.4.4 is the recursive Personal Pratibimba carrier, and the review/return path has a specific relational shape.

The correction is not to render the full map in the UI. It is to make the map addressable in the executable substrate so later capabilities have somewhere truthful to attach.

The general law is:

```text
Bimba coordinate/relation source
        ↓ exact structural identity
executable M coordinate + relation manifests
        ↓ same-path conjugate reflection
M′ capability bindings
        ↓
objects / events / Actions carry coordinate lineage
        ↓
Surface / instrument
```

A feature list is not an acceptable substitute for the coordinate/relation manifest.

## The parity vocabulary

Future Epi tickets and PRs should distinguish:

| Level | Meaning |
| --- | --- |
| **source parity** | accepted Bimba source corpus and revision are identified |
| **coordinate parity** | every in-scope coordinate has a stable executable Ref preserving root/path/parent/face/source |
| **relation parity** | constitutive source relations have typed executable counterparts or explicit gaps |
| **operational parity** | implemented behavior actually enacts the coordinate/relation it claims |
| **experiential parity** | the human/agent instrument expresses the right consequence without requiring architectural chrome |

Do not write simply “parity complete” where only one of these is demonstrated.

## Required build order for an M′ domain

Before substantial feature work in Mx′:

1. identify the accepted Mx/Bimba source scope;
2. inventory its coordinates and constitutive relations;
3. materialise/update the Epi-owned coordinate/relation manifest;
4. run manifest structural conformance;
5. map current native substrate to those coordinates without treating resemblance as ownership;
6. bind the first bounded Mx′ capability to its exact coordinate lineage;
7. build the Surface/instrument from those bindings;
8. test operational behavior and experienced use separately.

A Factory/coding agent should not jump from prose spec to feature implementation and create a local semantic enum as the de facto subsystem architecture.

## Structural invariants

The following are acceptance blockers:

- an accepted Bimba coordinate in the tranche silently disappears because no provider exists;
- a reflected M′ coordinate changes the Bimba path instead of changing only face;
- a recursive path is flattened into a sibling feature;
- a UI/component route becomes the canonical semantic identity;
- an Action or mutation bypasses an authored review/return relation;
- an M′ module invents its own incompatible coordinate namespace;
- coordinate existence is reported as implemented capability;
- provider availability is reported as semantic authority.

## Nara proving case

The first executable Nara parity floor now lives on `EpiLogos/Epi-Logos-C-Experiments` branch `agent/epi-nara-coordinate-parity`, stacked on Prompt-B producer PR #9 rather than touching the concurrent Prompt-C branch.

It adds a shared `portal-core` M-coordinate substrate and Nara manifest with:

- M4 root;
- M4-0 … M4-5;
- the complete first sixfold under every branch;
- #4.4.4.4 Personal Pratibimba;
- exact Bimba ↔ Pratibimba reflection Refs;
- containment relations;
- the first explicit lived-return relation chain:

```text
M4-4′
  └─ anchors-at → M4-4-4-4′
                    └─ supplies-evidence-to → M4-5′
                                                └─ governed-return-to → M4-0′
```

The Prompt-B daily episode now identifies M4-4′ as its instrument coordinate, #4.4.4.4 as its protected carrier, and M4-5′ as the review/relay seam. The old coarse `epi:bimba:#-4/M4'` world address remains compatible but no longer carries the whole burden of semantic location.

This is deliberately described as a **structural floor**, not full Nara deep-map parity. Current canonical Nara prose references a 100-node / 284-relation machine dataset at a repository path which is not present in the current source checkout. The missing canonical machine source must be recovered or superseded before claiming exact deep-node/relation coverage; fabrication is forbidden.

## QL-MEF's role

QL-MEF should make this law visible in the Wayfinder and development gates, but it must not absorb Epi's domain map.

The split remains:

```text
Epi/Bimba
  owns M-domain coordinate meaning + M′ reflection semantics

QL-MEF
  owns general QL/MEF formal machinery and can witness structural/reflection conformance

O:I
  hosts the resulting stable Refs / Surfaces / Actions
```

A future generic coordinate type may move downward only if it is genuinely domain-independent. The Nara/M4 manifest itself remains Epi-owned.
