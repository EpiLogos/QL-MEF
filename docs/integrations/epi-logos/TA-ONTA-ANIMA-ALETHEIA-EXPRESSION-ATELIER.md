# Ta-Onta Anima / Aletheia Expression Atelier Protocol

**Standing:** owner-directed live proving protocol, 16 September 2026.  
**Parent:** `TA-ONTA-EXPRESSION-SDK-WAYFINDER.md` / QL-MEF #201 / PR #202.  
**Material owner:** `EpiLogos/Point-Cloud-Demo` #6 and `field-studies-journeys/docs/AGENT_EXPRESSION_ATELIER_PROTOCOL.md`.  
**Corpus consumers:** `TA-ONTA-EXPRESSION-CORPUS-PRODUCTION.md` and `EpiLogos/Antykathera-Essay-Work#65`.  
**Purpose:** make Expression-corpus development a live Ta-Onta act in which the same Agent-world protocol being built is exercised by the Agents who build the corpus.

---

## 0. Why this protocol exists

The Ta-Onta Expression SDK should not be validated only by schemas and isolated fixtures and then later handed to an unrelated content-production process.

The Expression corpus is the first sustained opportunity to make the SDK **inhabit its own world**:

```text
source-bound epistemic object
        ↓
Khora · Hen · Pleroma · Chronos
        ↓
Anima situated creative act
        ↓
actual running Point-Cloud-Demo Expressions instrument
        ↓
material result
        ↓
Aletheia witness · critique · curation · praxis
        ↓
Return / revision / reusable Method candidate
```

The resulting corpus is therefore simultaneously:

1. submission content;
2. real SDK/API conformance evidence;
3. a school in how Agents can use the medium well;
4. the source of later Anima Skill/Method refinement.

The medium is treated as something an Agent learns to **play**, not a renderer receiving generated presets.

# 1. Native ownership

Ta-Onta does not move the Expression editor or engine into QL-MEF.

```text
Point-Cloud-Demo / O:I
    actual Expression editor + engine + Atelier service + artifact Library

Antykathera / Bimba / native Wiki owners
    semantic content and relation authority

Ta-Onta
    world entry, form horizon, capability/currentness, situated act and Return

Actuation / AIKit
    Agent/Agency, capability resolution, sessions, authority and specialist composition

Factory
    developmental changes when the returned problem is software rather than one Expression
```

The Atelier protocol is an **Epi domain use of the generic O:I Expression substrate**. It must remain possible for ordinary non-Epi agents/humans to use the editor without Ta-Onta.

# 2. One live Atelier world

Ta-Onta should resolve a local Point-Cloud Atelier capability which reports the exact running editor/engine/schema revision and exposes structured authoring over the same model the human UI uses.

Representative capability:

```text
ExpressionAtelierCapability {
    service_ref
    provider/body revision
    editor revision
    engine revision
    expression schema support
    available operation families
    parameter/action registry
    session capacity / resource state
    degradation
}
```

A successful Pleroma resolution gives Anima this capability. It does not give Anima a parallel in-memory scene DSL.

The exact operation vocabulary remains owned by the Atelier implementation and `oi.expression/v1`; Ta-Onta consumes discoverable stable refs/actions.

# 3. Six-organ live act

## S0′ Khora — establish the studio/world

For one production target, resolve:

```text
world / Project
canonical content subject
source + relation revisions
corpus / family / branch
existing Expression artifact if present
profile basis
Point-Cloud Atelier capability
AtelierSession continuation or new session
```

Return one exact entry reading. If the source revision or Atelier provider cannot be reconciled, entry refuses honestly rather than beginning from stale folklore.

## S1′ Hen — disclose form without deciding it

Hen resolves the available form horizon:

- inherited ExpressionProfile lineage;
- current scene/family precedents;
- glyph/image/ASCII/form occurrences already admitted;
- source-native visual or diagrammatic material;
- canonical page/verso/portal relations;
- authored variants;
- source/rights/standing.

Hen does **not** perform global asset procurement before content work. New forms emerge because the particular composition asks for them.

## S2′ Pleroma — disclose the actual powers available

Resolve:

- real Atelier service and supported actions;
- current M/M′ instruments/readings useful for this subject;
- source/Wiki/portal Actions;
- capture/media capabilities;
- available specialist Agents;
- prior recognised Expression Methods/Skills;
- absent/degraded capabilities.

Keep:

```text
available != selected != disclosed != permitted != invoked
```

## S3′ Chronos — bind the creative occasion

Chronos binds:

```text
source revision
Bimba/Wiki revision where applicable
profile revision
editor/engine revision
AtelierSessionRef
Expression working generation
scene/checkpoint generation
iteration lineage
capture/performance occasion
```

An Aletheia comparison must know which exact act it is comparing. A style pattern discovered on engine revision N is not automatically current on engine revision N+k.

## S4′ Anima — compose and perform

Anima owns the **actual mutation/performance** of the Expression under present authority. Its suboffices are below.

## S5′ Aletheia — receive and metabolise what happened

Aletheia owns observation, critique, admission, comparison and praxis candidate formation. It does not gain source-authority or automatic Expression mutation by observing the result.

# 4. Anima subagent/team offices

These are stable relational offices for development/proving. They may be embodied by one Agent or several coordinated subagents. The office identity is retained in operation receipts so later Return can ask **which relation to the work made this decision**.

## `anima.composition` — Composer / director

Carries the whole.

It is responsible for:

- scene and branching grammar;
- hierarchy, balance and emphasis;
- which material belongs together;
- scene-versus-sequence decisions;
- relation of optional text to material expression;
- the role of quiet/absence;
- framing intent;
- continuity with the source packet and neighbouring Expressions.

It does not need to manipulate every numeric field itself. It determines the compositional burden which material/temporal offices realise.

## `anima.material` — Field artist / iconographer

Works directly with the actual material language:

- particles, formations and pins;
- glyph/text/image/ASCII sources;
- visual-source sampling and variants;
- scale/density/contrast/legibility;
- material/field parameters;
- palette and semantic colour;
- resonance/cymatics;
- force/relational behaviour;
- object form and arrangement.

**New glyphs/images/ASCII/forms normally arise here from the actual content need.** The office may search, derive, author or adapt the form according to source/rights policy, then tests it in the running Expression before proposing it for reuse.

## `anima.temporal` — Choreographer / performer

Works in time:

- scene duration/transition;
- camera/framing passage;
- automation and property takes;
- focus movement;
- morphing and resonant passage;
- dwell/pause;
- playback/performance through the real engine.

It distinguishes a composition whose operation is already present in stillness from one whose meaning depends on movement or transformation.

## `anima.integration` — Expression integrator

Maintains the relation to the wider world:

- exact content/graph/source refs;
- Expression/profile lineage;
- portal/native Action relations;
- corpus/family continuity;
- merge of proposals from creative offices;
- one revision-safe candidate handed to Aletheia.

When several Anima subagents act on one Expression, this is the single mutation-integration office; parallel contributors do not race-write the live scene.

# 5. Aletheia subagent/team offices

## `aletheia.witness` — Witness

Records what materially happened:

```text
basis generation
actual operation receipts
engine/readiness state
captures / performance evidence
material differences
failed/degraded operations
intended effect vs observed effect
```

It prevents later discussion from treating intention as observation.

## `aletheia.critic` — Critic / comparator

Evaluates this particular Expression against its burden:

- content/source fidelity;
- legibility;
- relational clarity;
- expressive force;
- pacing;
- associative coherence;
- overstatement / under-articulation;
- corpus continuity;
- whether a medium feature is integral or decorative.

Its output is a basis-bound proposal/critique, not a hidden mutation.

## `aletheia.curator` — Curator / archivist

Admits accepted work into the Point-Cloud repo Library and records:

- exact artifact revision;
- source/profile/engine basis;
- cover/evidence captures;
- content-arising asset provenance/rights;
- subject/motif/Being/Thing occurrence tags;
- sibling/variant relations;
- useful rejected alternatives as evidence where warranted.

The Library becomes the durable world of **what was actually made**, not a new semantic source store.

## `aletheia.praxis` — Praxis crystalliser

Compares this act with previous acts to identify reusable practice.

It may produce an `ExpressionPracticeCandidate` carrying:

```text
name / provisional operation
examples
counterexamples
content/scene families where observed
engine/profile basis
why it appears to work
known failure modes
applicability / exclusions
unresolved questions
```

No candidate is a recognised Method merely because one scene succeeded.

# 6. Content-local asset emergence

The earlier corpus-map idea of a separate visual-asset procurement lane is superseded by this live practice.

Current law:

```text
content lane
  → live composition
  → form need becomes concrete
  → source/create/adapt glyph|image|ASCII|diagram|form
  → try it in the actual medium
  → accept/reject/variant
  → Aletheia curator indexes admitted occurrence
```

Cross-corpus asset discovery is therefore **derived from actual occurrence**.

Hen can later answer:

```text
subject / motif / coordinate
  → admitted visual forms
  → exact prior scene occurrences
  → provenance / rights / standing
```

Aletheia can answer:

```text
form / asset
  → where it was used
  → whether it worked in those offices
  → where it failed or changed meaning
```

This is a better basis for learned artistic practice than a catalogue assembled without material use.

# 7. Colour as an associative field with explicit standing

Colour is likely to develop strong cross-expression associations. Preserve those relations without collapsing them into one truth layer.

An important colour determination records its office, for example:

```text
SOURCE_BACKED_CORRESPONDENCE
M_OR_REGISTER_NAVIGATION
SUBJECT_OR_FIGURE_ASSOCIATION
AFFECTIVE_SCENE_CHOICE
MATERIAL_LEGIBILITY
EXPERIMENTAL_ASSOCIATION
```

A colour relation can carry several offices if explicitly named.

Repeated use may create an authored/pedagogical convention. This is a **practice/association Return**, not evidence that the colour is intrinsically identical with the subject.

Aletheia should preserve useful counterexamples: if an established palette association damages one source scene, the exception teaches the Method's boundary.

# 8. Learning the medium — Anima Skill formation

The artistic-learning loop uses existing AW/T/T′/`= name` practice law.

```text
AtelierIterationReceipt
      ↓
Aletheia comparison across accepted + rejected variants
      ↓
ExpressionPracticeCandidate
      ↓
reuse on a later target
      ↓
observed transfer / failure / narrower scope
      ↓
human/native Recognition
      ↓
recognised Method / Anima Expression Skill refinement
```

The resulting Skill must remain currentness-aware and capability-aware. It tells the Agent how to enter the present Atelier, inspect its actual powers, compose through evidence-backed practices and recognise when the practice is inapplicable.

Do not crystallise the first corpus wave into one frozen style system. The aim is mastery capable of variation, not template lock-in.

---

# 9. Use the team to develop the team

Implementation of the Atelier service, Ta-Onta adapters and first production waves should use these offices where practical.

A representative first proving act:

```text
Khora: one real A/Mytheme/Bimba target + source revision
Hen: prior form/profile/asset horizon
Pleroma: actual Point-Cloud operations + relevant M faculties
Chronos: exact session/engine/currentness

Anima.composition: initial scene/sequence relation
Anima.material: field/form/glyph/image/colour work
Anima.temporal: perform movement/transition where needed
Anima.integration: coherent candidate revision

Aletheia.witness: capture real result
Aletheia.critic: return changes/counterclaims
Aletheia.curator: admit accepted revision/assets
Aletheia.praxis: one bounded practice candidate

Anima: apply/reject critique
        ↓
next corpus target tests transfer
```

This provides genuine TA0–TA7 pressure. A missing capability, stale basis, authority mismatch or bad agent-team boundary is a returned SDK/API fact to fix, not an inconvenience to route around.

The offices are versioned and refinable. Repeated corpus work may show that two offices should merge, one should split or a new specialist is useful. Such changes are returned findings, not silent drift.
