## 0. Authority discipline

Keep these epistemic classes distinct:

```text
AUTHORED POSITION / SOURCE
DESIGN / ARCHITECTURE COMMITMENT
IMPLEMENTATION FACT
OBSERVED RESULT
RESEARCH PROPOSITION
CURRENT DEVELOPMENT INFERENCE
```

Current code tells us what is real now. It does not retroactively define why the project exists. Authored source tells us what is meant. It does not prove what currently works. Returned reality may revise design or vision only through an explicit successor.

The same discipline applies to coordinate identity and implementation residency: a package location is evidence about where code lives, not automatic authority over what a coordinate means.

## Closure

The fourfold is useful because it lets us say, simultaneously and without flattening:

- what a subsystem **is** and which guardian carries its semantic identity (`M`);
- where that identity **stands technologically** (`S`);
- how it becomes **operative activity** (`S′`);
- how differentiated activity becomes a **deep compositional whole** (`M′`).

The distinction matters because ownership, authority and implementation remain heterogeneous. The return-together matters because the system is one sixfold intelligence rather than four unrelated taxonomies.
