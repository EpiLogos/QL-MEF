# Epi-Logos ↔ O:I Primitive / Ownership Map

**Status:** working canonical crosswalk for reconstitution  
**Parent:** QL-MEF #32  
**Wayfinder:** #30  
**R2 research:** #25 / PR #27

This document answers a narrow but load-bearing question:

> When an Epi concept/function is rebuilt on the current O:I product field, which existing primitive owns the generic relation, which Epi semantics remain local, and where is an explicit bridge required?

The goal is neither to force Epi nouns into O:I nor to preserve duplicate generic infrastructure.

---

## 1. Ownership law

Use five questions in order:

1. **What does the thing mean in Epi?**
2. **Is there already a native O:I/suite primitive for the generic relation?**
3. **Would using that primitive preserve or erase an Epi distinction?**
4. **Is the Epi concept a specialisation/provider/payload over it, or independently owned?**
5. **What source/authority controls mutation and return?**

A formal resemblance is not enough to transfer ownership.

# PART I — IDENTITY / GROUND

## 3. Human durable ground

### Epi concept
The human/personal source from which Nara can read and to which reviewed changes may return.

### Native owner
**Central authored/adopted source**.

### Epi specialisation
`PersonalGroundBinding` is an Epi-level binding between Central source and Nara personal model/state.

### Law

```text
Central source
   ↓ read/bind
Nara derived/composed state
   ↓ proposal
human review
   ↓
Central accepted source change
```

### Disposition
`operate-through` + Epi-owned binding.

---

## 4. HumanIdentity

### Generic relation
Stable identity handle/ref for a human actor.

### Native relation
O:I/field identity primitives and Central human-owned source may reference the human, but **HumanIdentity is not identical to Central prose or the Nara model**.

### Epi relation
Nara may maintain an `IdentityModel` bound to a HumanIdentity/source but does not become the identity handle itself.

### Non-identity

```text
HumanIdentity != Central Control/user prose != Nara IdentityModel != O:I Participant
```

## 5. Epi canonical Agent

### Epi concept
One of:

```text
Anuttara
Paramasiva
Parashakti
Mahamaya
Nara
Epii
```

These are persistent domain Agent identities.

### Native owner
**Actuation `Agent`** for generic enduring-agent identity.

Epi-authored constitution/profile/world meaning, knowledge, skills and domain pole.

### Runtime composition

```text
Epi Agent
→ Actuation Agent / Agency
→ AIKit Profile + SkillSet + Context + body resolution
→ Workcell materialisation
→ Factory Run/Evidence when developmental
```

### Disposition
`operate-through`; do not replace names/identities with generic O:I product positions.

### Law

## 7. AgentSession / harness / body

# PART VIII — MIGRATION TEST

## 44. Before creating a new primitive

A proposed Epi/O:I primitive must answer:

```text
What existing primitive fails?
Is the missing relation generic or Epi-specific?
Can it be a provider payload, contribution, action, evidence link or adapter?
Does another non-Epi product independently need it?
What authority/mutation semantics does it carry?
What semantic collisions would the new noun introduce?
```

If those answers are weak, keep the concept local or compositional.

---

## 45. Before removing an old Epi primitive/body

Ask:

```text
What meaning did it carry?
Which generic functions now have native owners?
Which Epi semantics remain after delegation?
Where is state/provenance moved?
Which old behaviours are intentionally superseded?
What parity evidence exists?
```

Do not equate "generic mechanics now have an owner" with "the Epi concept has disappeared".

---

## 46. Summary relation

The intended result is not a generic O:I system with Epi labels painted over it, and not a preserved parallel Epi runtime.

It is:

```text
QL-MEF formal/harmonic powers
          +
Epi domain computation / source / instruments
          +
Epi inhabitation constitution
          ↓ operating through
Central · Actuation · AIKit · Factory · Workcell · O:I shared field
          ↓
coherent human/agent Epi world
```

The primitive map exists to keep each term in that equation owned by the layer that gives it meaning.
