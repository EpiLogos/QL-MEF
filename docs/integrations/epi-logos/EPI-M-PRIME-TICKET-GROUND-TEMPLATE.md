# Epi M′ implementation ticket — Mark / Aim + Coordinate / Relation Ground

Use these sections in every substantial M0′–M5′ implementation ticket before feature acceptance is specified.

The purpose is to preserve **both poles of implementation integrity**:

1. recover the Whole / Mark the tranche is answerable to, so a locally competent implementation does not delete the reason the work exists;
2. preserve the exact Bimba coordinate/relation ground, so a partial implementation does not become the accidental ontology of an authored M subsystem.

The template therefore begins with **Mark / Aim Ground** and then keeps the existing **Coordinate / Relation Ground** unchanged in function.

PRE-D returned two additional coordinate laws which remain explicit:

1. source representation is part of provenance: exact spelling, alternate notation, rootless/meta refs and partial relations must be retained rather than repaired silently;
2. structural existence and operational readiness are different dimensions: a coordinate/ref can exist even when no capability/provider/Surface/Agent disclosure is present.

The current Covenant/Mark articulation adds a third development law:

3. source, Mark and Aim form a recoverable relation: the Agent's reading of the intended Whole is interpretive and must remain distinguishable from the authored/source marks which informed it.

```markdown
## Mark / Aim Ground

### Mark
- What Whole is this tranche answerable to?
- What larger Project / Epi parent / 3:3 composition / Context Frame Mark contains or conditions this local Whole?
- Why does this tranche exist inside that Whole?

### Source signals
- human-authored / canonical source which carries the leading signal:
- current accepted design/architecture which bears upon the Mark:
- relevant returned reality / implementation evidence:
- source standing distinctions which matter here:

### Mark-reading Claim
- current articulation of what the Mark requires:
- standing: authored position / design commitment / research proposition / implementation fact / observation / agent inference / other
- Evidence refs:
- unresolved or contestable parts of the reading:

The Mark-reading Claim is not the Mark and does not replace the authored/source material from which it was recovered.

### Aim
- What is this specific research/development/implementation tranche undertaking toward the Mark?
- What difference should this tranche make to the larger Whole?
- Which parts are discovery/recovery, which are implementation, and which are evidence/Recognition?

### Orienting Figure, if material
- Figure / precedent / metaphor / exemplary object:
- source / provenance:
- `ILLUMINATES` — what relation of the Mark does this Figure make more apprehensible?
- `BOUNDARY` — what semantic/formal/scientific/implementation Claim does the Figure **not** establish?
- praxical effect — what does the Figure change about understanding, design imagination or intended experience?

A Figure is optional. When present it must carry illumination and boundary together. Analogy does not become source authority merely because it is compelling.

### Recognition
- What should a human be able to encounter, understand or do when this tranche genuinely contributes to the Mark?
- What should an Agent be able to address, explain, inspect or operate?
- What returned evidence would expose a locally-correct / whole-wrong implementation?

### Parity acceptance
- [ ] **Mark fidelity:** the tranche can state the Whole it serves, the source signals which disclose it, and the current Mark-reading Claim without conflating those standings.
- [ ] **Aim fidelity:** local acceptance criteria state what contribution the tranche makes to the larger Whole, not only what files/functions were produced.
- [ ] **Figure discipline:** any orienting Figure states both `ILLUMINATES` and `BOUNDARY`; historical analogy is not used as formal/scientific proof.
- [ ] **Source parity:** accepted source/revision is explicit and the relevant source records were actually read.
- [ ] **Source representation fidelity:** exact notation/aliases/meta refs/partial records crossed by the tranche are retained explicitly.
- [ ] **Coordinate parity:** exact root/path/parent/face/source Refs resolve without depth flattening.
- [ ] **Relation parity:** source kind/endpoints/direction/provenance survive, or the source gap remains explicit.
- [ ] **Relation-class fidelity:** Bimba-source, QL-derived, reflection, implementation/runtime and research relations are not silently conflated.
- [ ] **Operational parity:** behavior enacts the claimed coordinate/relation rather than merely labelling it.
- [ ] **Readiness fidelity:** structural existence is reported separately from capability/provider/Surface/Agent-disclosure readiness.
- [ ] **Experiential parity:** the human/agent Surface expresses the relation appropriately without architecture-as-dashboard.
- [ ] **Recognition parity:** a reviewer can tell whether the returned implementation actually contributes to the Mark, including cases where local tests are green but the whole relation has been lost.

### Anti-flattening checks
- [ ] no local implementation description replaces the Mark / authored Whole;
- [ ] no generated Mark-reading Claim is silently promoted into human-authored source;
- [ ] no orienting Figure is promoted into Epi ontology by analogy;
- [ ] no new local coordinate ontology replaces the QL-MEF/source index;
- [ ] missing implementation does not erase a Bimba coordinate;
- [ ] recursive coordinates retain their full source path;
- [ ] alternate notation is resolved explicitly rather than silently canonicalised;
- [ ] missing/meta source relation endpoints are not invented;
- [ ] provider availability does not become semantic authority;
- [ ] implementation packet/module calls are not written back as Bimba-source relations;
- [ ] governed return/promotion is not replaced by direct mutation;
- [ ] UI routes/components are not canonical semantic identity.
```
