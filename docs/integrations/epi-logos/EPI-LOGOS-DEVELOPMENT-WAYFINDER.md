# Epi-Logos Development Wayfinder

**Parent:** QL-MEF #30  
**Architecture research:** #25 / PR #27  
**Status:** planned programme map; fine-grained implementation follows source/authority ratification

This file turns the consolidated Epi/O:I account into a development graph. It is deliberately whole-product: formal substrate, historical computational bodies, native O:I ownership, six Pratibimba instruments, personal internality, parent experience and return/evidence remain visible together.

---

## 0. Destination

Reconstitute Epi-Logos **through QL-MEF and the native O:I product field** such that:

1. QL/MEF/harmonic/music theory is a first-class executable substrate, independently useful and constitutive of the wider field;
2. M0–M5 computation and source-backed datasets survive with parity/provenance even when implementation language or packaging changes;
3. the six canonical Epi Agents run through Actuation + AIKit + Workcell + Factory rather than a parallel runtime;
4. Ta-Onta survives as Epi inhabitation law, not duplicate generic infrastructure;
5. M0′–M5′ are rebuilt as true composable Pratibimba instruments;
6. Central/Nara make human objective-internality durable but human-authorised;
7. the parent 0/1 field composes Cosmic and Personal Epi experience;
8. Epi worlds can project into O:I shared fields without confusing Projection with Pratibimba;
9. Epii/return lets evidence revise the system explicitly;
10. historical shells can be retired once their functions are demonstrably preserved or intentionally superseded.

## 10. Workstream entry conditions

Before opening a fine-grained implementation ticket, its parent should name:

- source-of-truth file(s);
- exact existing source paths/components;
- current implementation status;
- intended semantic owner;
- native O:I dependencies;
- preserve/port/supersede disposition;
- tests/evidence needed;
- non-identities that must not collapse.

If those are unknown, the work is still an orientation/research task rather than implementation.
