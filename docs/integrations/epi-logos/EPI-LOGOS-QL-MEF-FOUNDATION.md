# Epi-Logos / QL-MEF Foundation

**Status:** working formal/harmonic foundation account  
**Parent:** QL-MEF #31  
**Compatibility:** #39  
**Registry promotion:** #49  
**Wayfinder:** #30

This document records the relation between the authored Epi formal genealogy, the retained QL/MEF musical-harmonic derivations and the independently developed QL-MEF package.

Its central purpose is to prevent a recurring category error:

> A formal system having a coordinate/location in Bimba does **not** make that system merely a local semantic label, UI page or optional domain correspondence.

The coordinate locates the system genealogically. The package develops its executable power.

---

## 1. Product position

QL-MEF is the executable formal/refractive/harmonic package substrate through which Quaternal Logic and the Meta-Epistemic Framework can be developed independently and then composed into Epi-Logos and the wider O:I technological field.

The relation is recursive rather than extractive:

```text
Epi authored/formal genealogy
        ↓
M1 Paramasiva / M2 Parashakti
QL flowering / MEF-Vimarśā / harmonic derivation
        ↓ generalisable formalisation
QL-MEF executable package
        ↓ independently usable relations / lenses / harmonic powers
O:I products + Epi M/M′ instruments
        ↓ encounter / evidence / returned discrepancy
QL-MEF amendment candidates / renewed Epi source
```

QL-MEF is therefore both:

1. independently useful technological infrastructure; and
2. genealogically constitutive of the fuller Epi field.

Neither side erases the other.

## 2. Accepted current floor versus complete destination

Current accepted QL-MEF work establishes a deliberately bounded implementation floor:

- deterministic QL position/relation kernel;
- relation/conjugation families and degrees;
- MEF lens registry/refraction;
- meta-knowledge graph distinct from Bimba;
- source-aware refraction / return patterns;
- current Q1–Q5 implementation/test surfaces.

`docs/Q2-MEF-REGISTRY.md` currently excludes musical assignment and deeper harmonic structures from accepted Q2 scope.

Interpret this exactly as:

```text
implemented/accepted now
    !=
full product destination
```

The retained harmonic/music derivation remains an architectural/source input to be tested and promoted through #31/#39/#49.

## 3. Formal parent and the 4+2 relation

The Epi source repeatedly uses a generative parent relation that must not be flattened into six unrelated numbered states.

Working source form:

```text
# / 0-1 generative parent
        ↓
0 1 2 3 4 5
four explicate + two implicate / return positions
        ↓
5 → 0 return
        ↓
renewed / inverted 1/0 relation
```

QL-MEF must preserve the distinction between:

- position identity;
- relation between positions;
- operator producing a relation;
- conjugate/return degree;
- refraction through a lens/field;
- a rendered or musical realisation of those relations.

A UI should make these relations intelligible; it does not define them.

## 4. P / P′ and same-product face caution

The Epi coordinate genealogy uses P/P′ / Day-Night′ / Bimba-Pratibimba-like conjugate relations in its own formal language.

O:I also uses H/A faces (`H_i=P_i`, `A_i=P_i′`) for human-facing and agent-facing conjugate faces of the **same product**.

These structures may be formally related but are not automatically semantically identical.

QL-MEF APIs should therefore expose explicit relation/operator identity rather than rely on the prime mark alone.

## 6. Complementary axes and three squares

A strong retained structure pairs the six base lens positions as:

```text
0 ↔ 5
1 ↔ 4
2 ↔ 3
```

These generate three complementary axes / square structures. The source tradition associates them with different relational phases/fields rather than treating them as arbitrary pairing tables.

The exact naming/semantics of A/B/C and D1/D2/D3 across accepted QL canon and the retained musical derivation is a known provenance seam.

**Rule:** identical vertex sets reached by different operators are not necessarily the same relation.

#39 must classify each historical/current use as:

- exact alias;
- operator-specialised relation;
- harmonic realisation;
- superseded name;
- namespace collision.

Do not solve this by silently renaming one corpus to match the other.

## 7. Context Frames

The retained derivation uses seven Context Frames as a dynamical/relational grammar over the formal field.

For QL-MEF development, a Context Frame should be treated as more than a UI mode or presentation filter. It is a candidate **operator family / relational condition** that selects or transforms how the same underlying formal field is traversed or heard.

Before promotion, #31/#49 must establish for each CF:

```text
stable identifier
source definition
input structure
relation/operator effect
expected cardinalities
conjugate/return relation
musical realisation if any
fixtures/tests
current status: accepted | experimental | source-only
```

The 7 CFs combine with 12 lens anchors to form the important 84-state landscape.

## 8. The 84-fold landscape

The retained harmonic architecture repeatedly yields:

```text
12 lens anchors × 7 Context Frames = 84 lens-mode / mode-tonic states
```

This is not merely a number to preserve.

A promoted QL-MEF model should make a state recoverable through explicit coordinates such as:

```text
lens_id
conjugate/base side
context_frame_id
QL position / stage where relevant
harmonic anchor / tonic
source derivation version
```

Any rendered pitch/mode/shape should be traceable back to those coordinates.

## 9. Foundational musical ratios

The retained derivation and current kernels use a family of simple harmonic ratios, including:

```text
16/9
9/8      epogdoon / whole-tone relation
4/3      fourth
3/2      fifth
2/1      octave closure
```

The current C kernel already computes epogdoon, fourth and fifth ratios and uses them in a 12-stage descent/ascent tick.

QL-MEF must distinguish:

- ratio as mathematical object;
- ratio's role in a derivation;
- scale/interval generated from it;
- a pitch/frequency realisation;
- Epi semantic/cymatic interpretation.

The first four may become generic package capabilities where proved. The final semantic interpretation remains domain-specific unless independently justified.

## 10. Whole-tone bases, diatonic selection and modes

The retained musical account derives a richer field from two foundational whole-tone/generator bases, followed by cross/conjugate selection into diatonic/modal structures.

Important candidate structures include:

- two whole-tone bases;
- 3×3 square arrangements in both bases;
- six harmonic pairing families;
- CF-conditioned diatonic instantiation;
- major/minor as conjugate-form selections rather than unrelated scales;
- seven modes as systematic traversals/selections;
- the 12×7 mode-tonic field.

These must be promoted through deterministic generators and golden fixtures where the derivation is unambiguous.

Where the historical derivation contains competing formulations, preserve both with provenance until resolved.

## 11. Klein / double-cover interpretation

The retained derivation interprets the diatonic/harmonic field using a Klein/double-cover relation with conjugate traversals/crosses.

Treat this first as a **formal/topological proposition** that may explain operator structure, not as a licence to add decorative Klein-bottle visuals.

A useful executable promotion would show that the claimed cover/involution predicts recoverable relations among states and survives deterministic tests.

UI/pedagogy can then render the topology because the operator exists, not vice versa.

## 12. Coordinate-to-pitch recoverability

One of the strongest engineering requirements from the retained derivation is that sonic output should not become an opaque synthesiser layer.

For any promoted musical event, the system should be able to recover something like:

```text
formal source revision
lens / sublens
Context Frame
QL position / stage
harmonic ratio / generator
mode / tonic / pitch index
upstream Epi coordinate where applicable
render provider / tuning
```

Conversely, a formal coordinate should deterministically produce its permitted harmonic/musical interpretation under a given registry version.

This makes sound a genuine formal instrument rather than decoration.

## 13. Voice-leading, rhythm and process

The retained musical source treats movement itself as meaningful:

- relation traversal can become interval/voice-leading;
- process/phase can become rhythm or duration structure;
- harmonic trajectory can express return/inversion/conjugation;
- repeated formal transformation can be heard as phrase.

QL-MEF should therefore prefer APIs that expose trajectories/transformations rather than only static `coordinate -> note` lookup.

Possible generic shape:

```text
FormalState
   ↓ apply(operator)
FormalTransition
   ↓ harmonic_projection(registry)
HarmonicTransition
   ↓ provider materialisation
Sound / score / visual trace
```

The provider owns audio rendering. QL-MEF owns the formal/harmonic derivation. Epi owns the richer semantic/instrument relation where applicable.

The retained Epi harmonic/cymatic architecture includes an important 8+4 output/form relation, reflected in the M2′ audio/nodal account (`audio_octet[8] + nodal_quartet[4]`).

3. **Parashakti cymatic/correspondential semantics**, Epi-owned;

#31/#33/#34 should decide the exact package boundary through tests and consumers.


## 16. Meta-Knowledge Graph / Bimba bridge

QL-MEF's Meta-Knowledge Graph records and reasons over structures such as refractions, relation frames, evidence or formal metadata.

Bimba is Epi's canonical ontology/coordinate source.

They may reference one another, but the bridge must carry:

```text
source graph / node ref
source revision
QL-MEF formal frame / relation ref
projection/refraction derivation
provenance
status / confidence where inferred
```

Never copy Bimba into the meta-graph and then let the copy become silent authority.

## 17. Promotion discipline

A source proposition becomes an accepted QL-MEF executable feature only when it has:

1. explicit source/derivation;
2. stable identifier/schema;
3. deterministic generator or authoritative data source;
4. invariants/cardinalities;
5. golden fixtures/tests;
6. provenance-bearing output;
7. clear semantic/package owner;
8. at least one real consumer where appropriate;
9. explicit accepted/experimental status.

This is the work of #31/#39/#49.

## 19. UI / pedagogy consequence

A QL-MEF UI should be expressive and pedagogical **about the formal object itself**:

- show why a relation exists;
- show how a lens refracts;
- show the source and operator;
- play or visualise a harmonic relation when the registry supports it;
- allow traversal of the 12×7 field;
- make conjugacy/return tangible;
- keep formal state recoverable from rendering.

The UI is the instrument/teaching expression of QL-MEF. It is not the reason the formal package exists.
