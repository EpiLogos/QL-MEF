## 0. The determination

Ta-Onta is not an agent-themed wrapper around independently designed tools. It is the **S′ agent-world through which Vāk becomes situated, compositional action**.

The dual M′ reading gives that action two leading orientations:

```text
3:3 EXPRESSION ORIENTATION
    M4 / Nara / S4′ Anima leads
    living · dialogical · material · performative

4:2 TECHNĒ ORIENTATION
    M5 / Epii / S5′ Aletheia leads
    investigative · articulating · critical · returning
```

“Leads” does not mean that only one S′ organ is active.

Every complete act still passes through the whole Ta-Onta relation:

```text
Khora → Hen → Pleroma → Chronos → Anima → Aletheia
```

The orientation says which pole is foregrounded in the human/Agent experience:

- in the 3:3 Expression world, **Anima performs** a situated composition and Aletheia closes it through actuality/Return;
- in the 4:2 Technē world, **Aletheia leads inquiry, disclosure and refinement**, while Anima remains the office through which any accepted material change is actually performed.

This reciprocity is essential:

```text
Anima without Aletheia = unexamined execution
Aletheia without Anima = commentary without consequential making
```

The two orientations are therefore not separate runtimes. They are conjugate uses of one Vāk/Ta-Onta execution field over the same subject, source basis and native owners.

# II — C′ IS ANIMA'S COMPOSITIONAL EXECUTION LANGUAGE

## 3. C′ composes a situated act

The existing `ql.vak-composition/v1` producer is the composition language for a whole act. It sits above atomic Resolve expressions and below concrete native execution.

```text
ResolveExpression / Vāk relations
            ↓
C′ composition
  CPF · CT · CP · CF · CFP · CS
            ↓
Ta-Onta S′ inhabitation
            ↓
native Actions / Atelier / Factory / Workcell
```

The offices are fixed:

| C′ | Name | What it determines |
|---|---|---|
| `C0′ / CPF` | Category / Context Frame Polarity | participation regime: human-engaged dialogical or authorised autonomous undertaking |
| `C1′ / CT` | Content Type | what kind of material is being worked |
| `C2′ / CP` | Context Position | where the act stands in the developing whole |
| `C3′ / CF` | Context Frame | the constitutional/relational voice organising the act |
| `C4′ / CFP` | Context Frame Position / thread form | how plural work is composed in performance |
| `C5′ / CS` | Context Sequence | the actual passage, direction and depth through the positions |

Recording these labels is not acceptance. The chosen values must change real participation, material selection, addressing, execution topology, sequence or Return.

## 4. CT is the material vocabulary of composition

The current source gives a useful material progression:

```text
CT0  relation / dependency / assumption material
CT1  definition / source extract / vocabulary / specification
CT2  executable / test / Action / operation material
CT3  pattern / image / diagram / schema / recurring form
CT4  contextual situation + source + temporal/world relations
CT5  integration / synthesis / learning / Return
```

This is directly useful inside both orientations.

For Expression work, CT helps Anima distinguish whether a scene is carrying a relation, a source statement, an actual operation, a pattern/image, a situated world or an integrating return. For Technē work, it determines what a deep instrument is manipulating rather than reducing every instrument to generic nodes.

## 5. CP and CS make development a passage rather than a task queue

Context Position remains:


Direction and extent are distinct. Returning inquiry asks what the performance failed to reveal; it is not merely replay in reverse.

This is the execution-level reason that a Journey, an Expression sequence and a development run can all possess a meaningful **path** without sharing one persistence ontology.

# III — CFP IS THE NATIVE GRAMMAR OF ORCHESTRATION

## 6. “Orchestration” means composition

Factory's accepted implementation makes the intended meaning explicit. Orchestration is not primarily scheduler administration. It is the **art of composing differentiated voices, materials and Returns into one developmental performance**.

The six CFP forms are:

| CFP | Work form | Musical/compositional reading | Native consequence |
|---|---|---|---|
| `CFP0` | one voice | single voice | one situated actor/undertaking |
| `CFP1` | independent parallel | chord | independent contributions with preserved identity/barrier |
| `CFP2` | chained | melody | one actual Return becomes the next contribution's material |
| `CFP3` | fusion | fusion / cadence | plural readings retained and synthesised without erasing voices |
| `CFP4` | sustained | drone | long-running work with continuation, checkpoint, explicit stop/recovery |
| `CFP5` | nested/meta | canon | one composition/orchestration becomes a participant inside another |

And the governed developmental cycle is:

```text
Z = compose → perform → record → rehear → recompose
```

Factory #217 has already materialised these forms through existing `ExecutableOrchestration`, Workflow/Run/Attempt/Delegation/barrier/Return machinery. Factory is therefore the **native developmental performance body of C′** when an undertaking is commissioned developmental work.

This does not make every Anima act a Factory Run.

## 7. Native executor selection follows the act

The same Vāk/C′ composition can be materially realised through different native owners:

```text
Expression / artistic act
    → Point-Cloud Atelier + oi.expression native operations

ordinary direct product act
    → canonical native Action / AIKit resolved capability / Actuation authority

commissioned developmental act
    → Factory Commission / Journey / Run / ExecutableOrchestration

material placement / service / body
    → Workcell
```

The composition language is shared; semantic and mutation ownership remains native.

This is the correct relation between the Atelier and Factory:

```text
Atelier
    artistic/material performance of the Expression

Factory
    developmental performance when the medium/system itself must change
```

A scene edit should not be inflated into a Factory Journey. A renderer defect discovered while making the scene can become a Factory Journey without losing the originating Expression/source occasion.


Ta-Onta therefore supplies neither a second capability registry nor a second workflow engine. It is the inhabitable relation among the existing ones.

## 17. Negative cases are first-class

- stale source/profile/QL binding;
