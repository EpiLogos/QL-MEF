## 6. Personal authority and Central NOW

Prompt C consumes the current Central NOW/DAY contract rather than introducing an Epi-owned personal canon store.

A Personal proposal has:

```text
sourceClass = proposal
adoptionState = unreviewed
sourceMutationPerformed = false
```

When Central is configured, O:I calls Central only through its canonical machine Action surface:

```text
ctrl --json action run projectcentral.now.return <input>
```

The return carries proposal/episode/selection/coordinate/evidence refs and a safe status statement. It deliberately does **not** copy the protected Nara sentence or generated proposal body into Central NOW.

Rejection is a distinct valid path: the NOW handoff can be resolved without adoption. Durable human personal source remains a separate recognition path. Central itself requires an already human-owned `ProjectCentral/now/user/**` source plus `acceptance=human-accepted` for `projectcentral.now.promote` to human ground.

Therefore:

```text
Epii proposal
  != human authorship
  != durable Central source mutation
  != Epi/QL canon amendment
```

## 7. Return classes remain distinct

Prompt C does not add a generic `return()` mutation. The four programme return classes remain separate:

1. **Formal-model return** — QL/Epi domain recurrence or formal computation.
2. **Operative software return** — code/artifact/project change through native Factory/project mechanisms.
3. **Epi theory/canon return** — amendment candidate requiring Epi/QL recognition.
4. **Human Personal return** — Nara-derived proposal requiring human recognition in human-owned source.

Prompt C primarily implements a read/review/orientation path plus class-4 proposal formation. It does not conflate those with classes 1–3.
