The unit is **a real Epi capability**. Do not begin from a technology list.


Current implementations may move. The reason the capability exists must remain available alongside its carriers.

## 4. Seven passes

### A — whole purpose

Recover what the subsystem/capability is **for** before implementation.

```text
What human/Agent experience was intended?
Why does this capability belong in Epi?
What larger relation fails if it is absent?
```

### B — semantic and experiential determination

Recover M meaning, M′ instrument, source coordinate/relation, human experience and Agent experience. Do not infer M from whichever service currently computes a value.

### C — Agent-world determination

For all six Ta-Onta organs ask:

```text
Khora     what ground/entry/continuity does the Agent need?
Hen       what semantic/artifact form must it inhabit?
Pleroma   what powers/models/instruments must be available?
Chronos   what time/cosmic condition qualifies it?
Anima     how does it compose into situated Agency?
Aletheia  how can activity become Knowledge/Evidence/Return?
```

Every intersection must be considered before being marked inactive.

### D — current O:I embodiment

Only after A–C inspect current native owners:

```text
Central    source / human / Project ground
Actuation  Agent / Agency / authority / Return
AIKit      Context / Knowledge / Capability / Method / model / composition
Factory    Project / Journey / Run / Evidence / Recognition
Workcell   material/provider body
QL-MEF     QL / MEF / Vāk / Context Frame
O:I        SharedField / Projection / Encounter / whole-world relations
```

Reuse native identity. Do not mint Epi duplicates of generic owner objects.

### E — provider/technology disposition

Record technology by capability served:

```text
provider
→ capability served
→ current owner/binding
→ Ta-Onta organ(s)
→ Epi semantic relation
→ current status
```

Use `CURRENT-PROVIDER | COMPATIBILITY-PROVIDER | HISTORICAL-IMPLEMENTATION-EVIDENCE | REPLACED | RESEARCH-CANDIDATE`.

### F — current reality

Inspect exact code/tests/receipts/providers/revisions. Distinguish `specified | implemented | tested | live | provider-absent | dataset-missing | degraded | review-pending | research-only`.

### G — Return

Ask what use/reality revealed, what Evidence/Reading/Observation exists, what may become a Candidate/proposal, who owns Recognition, and which source may legitimately change.
