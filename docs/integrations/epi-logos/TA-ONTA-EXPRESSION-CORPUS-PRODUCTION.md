```text

                ↓
           TA-ONTA S′
```

# 1. Graph = Expression field

## 1.1 One relation state, several presentations

The canonical graph/Wiki/Bimba owner remains the semantic authority. Expression does not become another graph store.

Operationally, however, the selected bounded graph whole **is the field being expressed**:

```text
canonical subject / coordinate / Wiki node
        ↓
bounded local whole
        = exact node refs
        + exact typed relation refs
        + readings / properties / source standing
        + unavailable / unresolved relations
        ↓
ExpressionGraphBinding
        ↓
Expression entities + relation presentations + formations
        ↓
material / spatial / textual / sonic / glyphic inhabitation
```

`LIST`, `TREE`, `GRAPH`, page/minigraph and `EXPRESSION` are alternate presentations/refractions over the same attributable relation state where their source scope is the same. They are not independent semantic worlds.

Changing graph location changes the active Expression subject/state. Focusing a bound Expression entity/relation updates the same shared selection/focus refs used by graph/page/Nara. Back/forward, pin, follow and recenter retain canonical subject/relation identity.

The ordinary resting experience may therefore be the Expression itself. A conventional graph rendering remains a summonable optic/aperture over the same field, not mandatory permanent chrome.

## 1.2 Constellations are layout grammar, not edge generation

QL constellation/harmonic forms operate over the exact relation set already supplied by the owner:

```text
bounded relation state
    + applicable QL shape / pair / triad / whole / direct-conjugate grammar
    → derived layout / formation / emphasis
```

A constellation may determine placement, grouping, symmetry, harmonic distance, transition grammar or visual/formal emphasis **only where its structural axes are legitimate for that source field**.

It may not:

- create a semantic edge because two things are visually adjacent;
- promote a derived spatial resemblance into canonical source meaning;
- replace the Bimba/Wiki relation IDs with renderer-local edges;
- erase unavailable, disputed or partial relation standing merely to complete a shape.

Partial constellations remain legitimate.

## 1.3 SharedField preserves the same law after projection

For SharedField/Explore:

```text
private/local canonical bounded whole
        ↓ Projection / audience filtering
admitted shared refs + relations
        ↓
shared ExpressionGraphBinding
        ↓
shared Expression-space
```

The shared Expression is generated from the admitted relation subset. Private refs do not exist in the shared binding merely because the local Expression knows them.

Two independently grounded worlds may therefore inhabit one shared Expression field while retaining separate private graphs/Nara contexts and exact source-return paths.

# 3. Scene ontology and native portals

O:I #352 owns the generic substrate increment. Ta-Onta consumes it through Hen; QL does not create a parallel scene schema.

An Epi Expression must be able to sequence scenes whose primary body is, as applicable:

- a live engine composition;
- a canonical text/Markdown source or selected span;
- a glyph/SVG/ASCII target;
- an image/media/diagram;
- a generic native file Thing;
- a Wiki/Bimba bounded local whole;
- authored HTML / WorldPresentation / native Surface;
- Nara/Epii or another admitted Being Surface;
- another Expression/Edition under recursion limits.

Unsupported file types remain valid scene subjects but degrade honestly to a bound Thing/preview/fallback plus native open Action.

Scene triggers are declarative references to existing Expression operations, SurfacePortal operations, focus/navigation operations or native ActionRefs. They are not arbitrary renderer scripts.

This makes canonical-file pop-outs part of the Expression grammar:

```text
scene / entity / text cue
    → exact source_ref
    → portal.open(beside | full | detached | ...)
    → native Surface
    → re-dock / Return
    → same Expression + scene + selection
```

# 4. Hen visual vocabulary: glyph / image / ASCII / form occurrence system

The generic reusable asset-ref/index contract belongs to O:I #352. Hen supplies Epi semantic bindings over it.

For Epi use, an asset occurrence may additionally resolve:

- Bimba coordinate/branch refs;
- M family / M′ instrument relation;
- Symbolon/Matheme/Mytheme/Episteme register refs where the subject comes from the essay world;
- Being/Thing/figure/object/motif/element/place roles;
- exact whole-Mytheme occurrences;
- source standing and rights/provenance;
- authored versus generated form standing;
- current Expression/Profile/Scene occurrences.

Required lookup:

```text
being / thing / motif / coordinate
    → available glyph/image/ASCII/form variants
    → all Expression occurrences

asset
    → exact source/rights/provenance
    → all subjects it is admitted to depict/signify
    → all Profiles/Expressions/Scenes which use it
```

Do not make one image the meaning of a figure. The occurrence system exists precisely so variation across Expressions remains visible.

M3 glyph/form identities may supply source-backed forms. Mytheme figures may have authored/source images. ASCII is a first-class textual fallback/visual target where useful. Generated forms retain generated standing.

# 5. Corpus production: two bounded source worlds

## 5.1 Bimba Atlas

TA1 remains the owner. The production run is deterministic over the existing Bimba registry and current source/capability field.

Do not hand-author one file per node.

For the requested first submission cut, produce inhabitable Expression/profile coverage across the selected **2–3 meaningful registry depths** by resolving the real branch paths rather than inventing a new depth ontology. Each generated address retains parent/child/local-neighbour refs and exact profile lineage.

A coordinate or branch can later receive an authored variant without changing its canonical Bimba identity.

## 5.2 Return of Zero authored world

The essay repository already owns the ontology. Ta-Onta consumes it; it does not reinterpret it.

The production target is the current canonical authored-world census, including:

- `section-rooms/` and their section/subsection/movement relations;
- the four Vāk registers: **Symbolon · Matheme · Mytheme · Episteme**;
- the current A / A′ / C / A/C / S relational suite;
- canonical concept records;
- every other canonical record in those four register trees which the source census marks as an authored-world page/carrier;
- declared paths/returns/transverse relations and exact source standing.

Do not hard-code historical counts as the census authority. At current T25 standing the shared A/A′/C/A/C/S suite is 144 records; the generator must still read actual canonical identities at the source revision it compiles.

Repeated families become repeated Expression forms rather than bespoke applications. For example, the A family may be one family Expression/sequence with one scene per current A record while every scene remains independently addressable; the same method applies to the other argument families, Concepts, sections and other repeated source forms.

The same canonical record may participate in several authored routes without being copied into several semantic identities.

## 5.3 Mytheme whole-story law

Mytheme is the exception to any temptation to compress everything into one-node/one-card scenes.

A Whole Mytheme Expression must carry the source whole far enough that **every active relation and transformation remains available and the ending/aftermath can qualify the beginning**. Its Expression may therefore be a genuine scene sequence.

Derived figure/object/animal/plant/element/place/action/motif/archetypal constellations link back to their exact whole-story moments. Cross-story asset/glyph recurrence is indexed through the occurrence system; it does not replace the whole.

Human-amplified interpretive standing remains intact.

# 6. Profile inheritance and corpus continuity

Use one explicit inheritance chain rather than page-local magic values:

```text
O:I global substrate profile
    ↓
Epi global profile
    ↓
corpus / register / M-family profile
    ↓
family / branch profile
    ↓
record / coordinate authored variant
    ↓
scene-local override / current encounter overlay
```

Corpus/global profiles should carry the continuity parameters which ought to remain recognisably shared:

- stage/material baseline;
- typography/text placement grammar;
- camera/framing defaults;
- particle/form scale and resource budgets;
- motion/damping/transition rhythm;
- reading-mode HUD and aperture rules;
- portal/pop-out presentation defaults;
- global glyph/image/text fallback policy;
- theme/reduced-motion policy.

M-family/branch profiles may add the established colour/material differentiation useful for navigating the six M branches. Where a colour correspondence is source-backed, retain its source standing; where it is merely interface differentiation, keep it explicitly presentational.

Intentional local variation remains possible through profile lineage rather than duplicated constants.

# 7. Parallel production protocol

Artifact preparation can begin before every live renderer seam is finished because the source worlds and their relations already exist.

## P0 — compile the source censuses and packets now

For each target record/coordinate resolve:

```text
canonical identity
→ canonical home / register / record_type / branch
→ exact source revision
→ incoming / outgoing / Return relations
→ bounded local whole
→ applicable ExpressionProfile lineage
→ scene/sequence plan
→ required native carriers / portals
→ asset/glyph/image/ASCII needs
→ canonical Actions
→ expected Expression/Edition output
```

Use target-keyed packets. Do not dump entire corpora into every worker.

Canonical declared relations and source-backed Bimba relations are first-class. Local/proximate link discovery may propose additional candidate relations, but candidates remain visibly derived/proposed until recognised by their native owner; visual proximity never silently creates graph truth.

## P1 — parallel specification/procurement lanes

Run disjoint sessions for:

- essay sections / section rooms;
- A family;
- A′ family;
- C family;
- A/C family;
- S family;
- Concepts and other Episteme repeated forms;
- Matheme;
- Mytheme whole stories + internal scene sequencing;
- Symbolon root/spine/heads;
- Bimba selected 2–3 depths / profile resolution;
- visual-asset procurement and rights/provenance;
- ASCII/glyph/form preparation;
- HTML/WorldPresentation scene templates.

Workers produce source-bound Expression specifications and asset manifests through the same protocol. They do not invent new semantic edges or new ontology.

## P2 — compile through the real APIs

Once O:I #352 and TA0/TA1 seams are executable enough, compile the prepared specifications through `oi.expression/v1` + Ta-Onta rather than converting them into a parallel scene-file format.

Every artifact records exact input/source/profile revisions and build receipts.

## P3 — retroactive source alignment

After any final T25/T26 essay revision or Bimba registry change:

1. rerun the canonical census;
2. diff identities/relations/readings against the previous build receipt;
3. regenerate only affected Expression bindings/scenes/assets;
4. retain intentionally authored variants;
5. report orphaned/retired source bindings rather than silently carrying them forward.

## P4 — corpus-wide expression alignment

Run a final continuity pass over the complete generated set:

- global/profile parameters actually inherited rather than copied;
- M-family colour/material differentiation coherent;
- camera/scale/typography/transition rhythm coherent where intended;
- repeated family scenes use the complete available engine vocabulary where useful;
- pages which should be deliberately quiet remain quiet;
- Mytheme story sequences remain whole rather than reduced to decorative symbols;
- every portal returns correctly;
- every asset occurrence and source/rights relation resolves;
- every graph/Expression navigation path retains canonical refs.

This pass may tune presentation/profile variants. It may not rewrite semantic source to obtain visual uniformity.

# 8. Joined acceptance / submission boundary

The Expression corpus is complete for the submission cut only when:

1. the in-scope Antykathera authored-world census is bijective with generated Expression coverage except for explicitly declared non-Expression carriers;
2. Symbolon, Matheme, Mytheme and Episteme are all represented as themselves, not collapsed into three buckets;
3. section-room and argument/concept/S coverage is complete at the source revision named by the build receipt;
4. Bimba Atlas coverage exists at the selected 2–3 real registry depths and resolves through TA1 rather than 1,875 hand-authored scene files;
5. graph navigation changes the active Expression state and Expression focus changes the same canonical graph/selection state;
6. constellation/layout grammar never creates undocumented semantic edges;
7. every scene can open its canonical file/page/Wiki/Surface where such a source exists and return without identity loss;
8. mixed scene bodies—live engine, file, HTML/WorldPresentation, Wiki local whole, glyph/image/ASCII—operate through the generic substrate;
9. Mytheme whole-story Expressions preserve the complete active narrative relation/transformational arc required by their source records;
10. reusable asset/glyph/image/ASCII refs have source/rights/provenance and occurrence traversal;
11. profile inheritance supplies corpus continuity and explicit local exceptions;
12. the M′/S′ alignment ledger has no unexplained orphan implementation or second graph/source/renderer authority;
13. SharedField projection proves the same graph→Expression law after audience filtering with no private-state leakage;
14. D/C/P/M/H evidence retains its actual standing.

This becomes a hard experiential/corpus boundary alongside the O:I product acceptance and environmental/material stress-testing boundaries. It does not substitute for either of them.
