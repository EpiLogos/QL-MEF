# Epi-Logos R2 focused deep-dive protocol

**Purpose:** turn the corrected second-pass orientation into bounded research sessions without asking one agent to understand the entire Epi/O:I corpus at once.

This protocol is for **research/mapping sessions**, not implementation sessions. Each session should produce an evidence-backed map and a short architectural synthesis, then stop for human interpretation before creating implementation work.

## Common method for every deep dive

Each session must:

1. Start from the actual current live GitHub state; reverify default heads and active successors that touch the seam.
2. Consume the accepted Epi R1 snapshot, but re-open the active domain/system specs and relevant implementation rather than mapping from R1 prose alone.
3. Begin with **purpose and experiential function**: what is this Epi domain/law trying to make possible or encounterable?
4. Separate:
   - Bimba/domain meaning;
   - M′ lived Pratibimba expression;
   - S/S′ historical embodiment;
   - generic O:I Cradle capability;
   - Epi-specific application/harness law;
   - current provider/body;
   - authority and state.
5. Treat the six Epi identities as canonical Agents and test how their persistent identity becomes an Actuation Agent/Agency plus AIKit/Factory execution without reducing the identity to a harness profile.
6. Read QL structurally but distinguish canonical QL form from software-architectural interpretation.
7. Record disagreements between source strata explicitly. Human correction is admissible architectural evidence and should cause a re-read rather than a defensive citation contest.
8. End with 3–7 consequential judgments/questions, not a huge generated backlog.
9. Do not close QL-MEF #25 or create implementation tickets unless the main R2 review has accepted the relevant conclusion.

## Required output schema

Each deep dive should return:

```text
PURPOSE
What this domain/law is for in the Epi-Logos whole.

EXPERIENCE
What a human/agent should actually be able to encounter/do.

BIMBA
Canonical M/domain form and authority.

PRATIBIMBA
M′ lived software expression.

AGENT
Canonical Agent identity, likely Agencies, VAK/CF relations.

HISTORICAL BODY
S/S′ functions and actual providers/implementation.

CRADLE MAP
Central / Actuation / AIKit / Factory / Workcell / Quaternal Logic support.

EPI RESIDUE
What remains specifically Epi after generic substrate is factored out.

PACKAGE SHAPE
Library/service/application/plugin/product pressures; state/authority reasons.

RETURN
How this domain contributes to P5/return, recognition and future ground.

TENSIONS
Conflicting source, QL/software mismatch, or unresolved interpretation.
```
