## 1. The agent's actual interface

An agent encounters code, mathematics, language and their structured execution. A tool description, a Skill description, an available schema, an exact source and a returned error are all operative parts of that interface. The agent must be able to find the appropriate practice from its present intention, then understand its inputs, authority, effects, output and failure before acting.

For each faculty disclose: stable native ref and owner; what it is for; activation circumstances; required subject/World/source revision and contextual fields; available versus supported status; current input/result schema and version; authority and effects; refusal/stale/partial-result behaviour; evidence/Return and continuation. Use source-qualified public descriptors from the actual owner. The twelve practices below are not twelve new APIs. Missing descriptions or schema fields are explicit owner work in #94/#133 and their native dependencies, not prose assertions that an operation exists.

For the language, full original musical C′ remains normative: CPF participation regime, CT content, CP position, CF frame, CFP thread and CS passage. Their effects must survive actual execution and Return. All 109 Vāk entries and the complete 36-cell operative field are the source; the Method names are navigation into that body. `METHOD:` belongs at the beginning of the **description**, not merely in a heading. A Method is the same Skill/resource identity, not another artifact store.

## 2. Source, discovery, loading and use are separately observed

| State to establish | Required evidence | What it does not establish |

The native loading owner is AIKit. O:I `docs/SUITE-OPERATOR-SKILLSET.md` assigns product-owned Skill source trees to native `source add-directory`, sync, review/trust, native sets and scope projection. O:I's shipped guardian set intentionally contains only O:I-owned Skills; do not copy QL Skills into that manifest. QL owns the files here; AIKit owns their registration, composition and projection.

The preparation and walk Methods are source-operable now. They can read the full plan and declare a missing prerequisite. The grounded generic service/adapter Skills retain their actual five-operation scope; full live field and Anima operations require their real producers. The report Skill can already return source-backed findings and human questions; automated T consumption and named registration still require their assigned native route.

### Native composition to verify, not assume

Compose a QL experience set from the returned native identities for:

- `ql-foundations`: bounded foundational meanings and exact shape discipline;
- `ql-mef-operation`: bounded existing QL service operation;
- `ql-experience-prepare`: full intent, source and readiness preparation;
- `ql-evidence-report`: pithy attributable report and human response;
- `ql-experience-walk`: actual lived verification when its prerequisites hold.

For implementation/graph maintenance, also include the source-owned `ql-mef-refraction-adapter-authoring` and `bimba-cypher` under the applicable scope. The graph method's presence never grants mutation authority. The native Cradle process Skill is contributed by O:I for actual Cradle units, not copied into QL or made the global K8 branch law.

Use the installed CLI's actual help and returned IDs; do not guess a capsule name from a folder. The controlled projection probe in `scripts/verify-ux-skill-projection.py` exercises the selected native AIKit version in a disposable home and is the executable example. A passed projection probe is still not a live model/harness-loading receipt. At the installed walk, remove one required Skill from the selected scope: the next fresh context must expose the absence rather than continuing from a stale copy. Restore it natively and repeat.

A projected Skill's repository-relative references are **source locators**, not assumed paths relative to the generated payload. Resolve them through the canonical QL source or its authorised source provider. Bundled support material remains in that Skill's own payload. Protected sources listed as provenance are not assumed accessible; use the available approved contract and identify the unrecovered provenance.

## 5. Bootstrap without circular dependence

### Bounded bridge B0 — source-grounded repository work

Inputs: this source tree or native GitHub access, the owner's assigned issue/story, actual current main and active issue coordination. Read the Wayfinder, source minute, linked practice and the exact relevant canonical source with the native connector. Run `python3 scripts/check-ux-spine.py --prepare UXnn` from a verified checkout, or read its resulting requirements through the same source access. Use available build/test tooling only for the supported implementation. Return exact source/tests/publication state to the existing issue or authorised NOW. No private Control mutation is needed.

This bridge can ground current repository work before installed skill projection is complete. It does not install a copied QL Skill into O:I, invent an agent API, or establish a full live session. It is retired for ordinary product operation once native discovery → current projection → harness loading → correct use has its own evidence. Repeated source pasting in a final user walk records a loading/continuity gap.

### Bounded bridge B1 — controlled Skill delivery

Use `scripts/verify-ux-skill-projection.py --aikit <actual-binary> --source-root <this-repo> --output <new-disposable-directory>`. The probe creates only its own isolated HOME/AIKIT_HOME/context, invokes real source discovery, review, composition and projection, checks exact current bodies, then disconnects and reconnects the selected Method. It must not write a person's Control, register a production Routine, call a commercial model or assume source trust. Its result is native delivery evidence only. Actual loading by Epii remains UX01's installed prerequisite.

### Bounded bridge B2 — readiness before the owner's walk

An operator fills the readiness questions with actual versioned owner observations before asking the person to begin. Missing ephemeris, unimplemented Action, wrong Nara scope, absent Skill, unavailable C′ join or unresolved local prototype revision is identified beforehand. Continue independent repository work; do not call a mocked or manually repaired route the final experience. On the owner's machine, reconcile retained local/remote work and the newer renderer first, through the existing native workflow.

## 6. Reports and retention

Use the report Skill for concise result/basis/open/decision. Retain exact owner refs, expected/actual source and generations, actor/subject, selected practice and loading evidence, actual calls and result/error, human correction, consumption destination, and the next dependency. A pending receipt remains pending after restart. A corrected report links to the earlier claim rather than silently replacing it.

NOW retains the current useful work and continuity; native source/evidence owners retain durable records. T/T′ consumption is not an instruction to delete evidence or private human scratch. Final experienced validation records the person's own response, including that it was not requested or not given. Static checks, screenshots and source-native tests remain supporting evidence.

### Native delivery evidence scope

The controlled probe uses the actual AIKit `source add-directory`, `source sync`,
`source promote`, `set create/show`, scoped `enable/disable`, `apply` and
`method list` commands. Directory-source promotion applies the native local
review policy; the probe hashes and reviews every controlled input before it.
AIKit Spec III §§1–1.2 establishes sets as folders with optional manifests. The tested writable set is a native folder with `members`; the command owns
that format. Membership and capability enablement are distinct, so the probe
shows the withheld set before enabling its members. It reads only the matching
current generation's Claude/Codex projection, then disconnects and reconnects
the preparation Method. It does not inspect stale generations as uptake.

Run the executable under its native basename `aikit` and supply the isolated
context declared by the probe. A different basename is a multicall command
entry, not the ordinary CLI. The probe preserves the complete Skill body and
companion paths without assuming those references were loaded by a model.
